<task type="auto">
  <name>Task 1: Add streaming response to generate endpoint with retry logic</name>
  <files>src/app/api/studio/generate/route.ts</files>
  <action>
Modify the existing generate endpoint to support streaming (progressive) responses using NDJSON (newline-delimited JSON):

1. **Streaming response format:** Instead of returning all items at once, stream each enriched item as a separate JSON line. Use `ReadableStream` with a `TransformStream` to write NDJSON lines. Each line is one of:
   - `{"type":"meta","suggested_title":"...","suggested_description":"..."}` (first line, after Gemini returns)
   - `{"type":"item","data":{...enriched item...},"index":N,"total":M}` (one per item as enriched)
   - `{"type":"done","total":N}` (final line)
   - `{"type":"error","message":"..."}` (if fatal error)

2. **Retry logic:** Wrap the Gemini call in retry logic: on first failure, silently retry once. On second failure, stream an error line with suggestion to try a different/more specific topic. Use a simple try/catch with one retry, not a retry library.

3. **Keep existing enrichment pipeline:** The IGDB/Wikipedia enrichment already works well. Stream each item as soon as its enrichment completes rather than waiting for all items.

4. **Concurrency:** Keep the existing `WIKI_CONCURRENCY = 6` for image enrichment. Process items in batches of 6 but stream each completed item immediately.

5. **Response headers:** Set `Content-Type: text/plain` (NDJSON), `Transfer-Encoding: chunked`, `Cache-Control: no-cache`.

6. **Keep backward compat:** Also keep the existing non-streaming behavior as the default. Add a query param `?stream=true` to opt into streaming. When `stream=false` (default), return the existing JSON response for backward compatibility.

Do NOT change the Gemini model or prompt -- the existing prompt works well. Just wrap the response flow in streaming and add retry.

**Studio store changes (`studio-store.ts`):**

1. Replace the `generateItems` action with a streaming version that calls `/api/studio/generate?stream=true` using `fetch` (not apiClient, since we need raw streaming).
2. Read the response body as a `ReadableStream`, split on newlines, parse each JSON line.
3. On `meta` line: update `listTitle` and `listDescription` if empty (same as current auto-fill behavior).
4. On `item` line: append the item to `generatedItems` array immediately (progressive reveal). Also update `generationProgress` to show `"Loading item {index}/{total}..."`.
5. On `done` line: set `isGenerating: false`, clear `generationProgress`.
6. On `error` line: set `error` to the message, set `isGenerating: false`.
7. **Error retry UX:** The retry happens server-side (silent). Client just shows progress. If the server sends an error line after retries, show the error message with a suggestion: "Try a more specific topic, or rephrase your request."
8. Keep the existing `excludeTitles` dedup logic (send existing item titles to exclude).
9. Keep the existing match-items POST call after streaming completes (for DB matching of new items).

**StudioItemsView changes:**

1. When `isGenerating` is true and items are streaming in, add a subtle enter animation to each new item (fade + slide up, 200ms, using Framer Motion `AnimatePresence` + `motion.div`). This creates the "progressive reveal" feel described in the context.
2. Show `generationProgress` text below the grid during generation (e.g., "Loading item 15/30...").
3. When generation completes, briefly flash "Generation complete!" for 2 seconds then clear.
